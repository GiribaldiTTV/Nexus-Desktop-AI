# Governance Intake and Reporting

`Docs/Main.md` routes source truth; `Docs/phase_governance.md` owns phase and acceptance boundaries. This file owns proportionate reporting, not execution authority.

Before an uncovered governance change, identify the actual problem, material owners, approval, carrier, affected proof and smallest coherent repair. An already admitted inventory and plan carry forward with relevant deltas. Do not repeat intake merely because work continues.

Routine internal progress reports actual changed effects, affected checks, material uncertainty and next admitted action. Link unchanged history rather than copying it. A complete decision or handoff packet is due at its actual material boundary, with clear subject, evidence, missing decision and limits. Honor USER requests for full detailed digests. Compact routine reports must not hide blockers, omit requested detail or substitute for human acceptance.

Use the existing selected publication contract and one current review subject. A new finding or evidence file does not automatically create a USER gate, ledger or publication lane. Ordinary escaped defects receive implementation repair and relevant regression proof; governance changes require a demonstrated governance cause.
