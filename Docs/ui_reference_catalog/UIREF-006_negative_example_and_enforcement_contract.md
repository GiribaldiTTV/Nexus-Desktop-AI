# UIREF-006 Negative Examples For Visual Claims

Reference ID: `UIREF-006`  
Reference Class: `Visual and interaction review`

Do not claim a product surface matches an accepted reference merely because a screenshot exists, a marker fired, or a helper returned PASS. Compare the actual rendered element groups and states against the relevant product reference. Reject duplicate views presented as different states, missing full-window context for placement claims, and controls that are visible but do not perform the claimed action.

Templates, screenshots, shared primitives, and product standards serve different purposes. A borrowed component still requires verification in its consuming window, including text, focus, hover, disabled and error states, geometry, accessibility, and truthful backend mapping. This document describes negative examples; it does not imply that automated enforcement exists.
