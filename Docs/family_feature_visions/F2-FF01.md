# F2-FF01 Nexus UI Reference System

Family Feature Vision ID: `F2-FF01`
Parent FAM: `FAM-002`
Feature Category: `Nexus UI Reference System`

This category defines consistent Nexus-owned windows, controls, dialogs, status surfaces, and tray doorways. A reference is a comparator for its stated surface and states. An implementation must still demonstrate its own rendered behavior, accessibility, and platform exceptions.

## Reference Classes

- `F2-FF01-E01`: Top-level window frame and chrome, including close, minimize, maximize, restore, drag, and resize states.
- `F2-FF01-E02`: Buttons and controls in primary, secondary, danger, disabled, hover, focus, pressed, selected, dirty, loading, empty, and error states.
- `F2-FF01-E03`: Dropdowns, menus, lists, filters, cards, rows, and dividers.
- `F2-FF01-E04`: Modal and child windows, confirmations, platform-native exceptions, and troubleshooting surfaces.
- `F2-FF01-E05`: Status, degraded, blocked, fatal, recovery, support, and diagnostic panels.
- `F2-FF01-E06`: Tray and menu doorways, settings entry surfaces, and their route states.
- `F2-FF01-E07`: Geometry and responsive layout across minimum, default, medium, wide, maximum, fullscreen, DPI, and multi-monitor conditions.

`Docs/ui_reference_catalog/` provides the detailed UIREF comparators. Use only a comparator applicable to the actual surface and state. Known limitations remain visible; a generic reference or a single screenshot cannot establish that an implementation behaves correctly.

The feature owning a visible surface also owns its behavior and failure states. FAM-002 supplies shared presentation grammar; FAM-001 owns launcher failure behavior, FAM-003 resident/settings doorways, FAM-006 monitoring and recording surfaces, FAM-007 AI and trust surfaces, and FAM-008 installation and setup. New tokens or shared primitives should be introduced only when they improve real same-class consistency, without expanding the product feature by implication.
