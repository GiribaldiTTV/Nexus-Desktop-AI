# Nexus Desktop AI Source-Truth Router

## Purpose and baseline

This file routes a task to its material source-truth owners. It is an index, not a copy of their policies or a live status record.

The canonical product repository is `D:\Nexus Desktop AI\Product Repository`. Verify its Git root and current `origin/main` before relying on this router. `origin/main` is the merged product baseline; public tags/releases prove released-version truth. Worktrees under `D:\Nexus Desktop AI\Worktrees` are separate Git carriers. Their files are branch evidence until merged. `C:\Nexus Desktop AI` is the retained rollback predecessor, not the current router. `Docs/nexus_workspace_roots.md` owns the workspace-root map and historical path interpretation.

For a mutation, verify the exact carrier root, branch, HEAD, upstream, merge base, ahead/behind, dirt and ownership immediately before acting. Neutral main is protected. A current USER authorization must identify the permitted write carrier and scope. A checkout, plan, receipt, helper result or review packet does not grant that authority. Local commit, push, PR mutation, merge, release, publication and live activation are separate actions subject to their applicable authorization and owner contract.

Git/GitHub own volatile ref, PR, issue, tag and release facts. The matching external operational owner under `D:\Nexus Desktop AI\Governance State` owns current phase, assignment, locks, planning and next action. `D:\Nexus Desktop AI\Governance Control Plane` holds installed operational Governance contracts and implementation, routed by `Docs/governance_efficiency_operating_model.md`. `D:\Nexus Desktop AI\USER` holds selected review evidence and transport, not source authority. Historical paths, packets and branch overlays are evidence.

Do not load `Docs/nexus_startup_contract.md` by default; load it when that loader itself is explicitly analyzed, changed or directly validated. A summary, marker, old prompt or historical receipt never overrides an active owner. Report a material conflict before the affected mutation.

## Decision and evidence boundary

Check actual USER authorization, active owner and evidence for the operation. Approval carries within its stated scope and expiration; a new seam, artifact or helper result does not automatically create a USER gate. An uncovered decision, phase transition, protected effect or required human result remains separate. Source/fixture qualification, actual host/runtime result, independent review, USER result and post-merge result cannot substitute for one another.

Publication and handoff use the current selected USER review contract. Internal candidate archives are not additional USER-facing selections. Preserve historical packets. One current subject must agree with selected files, transport, detached receipt and digest link.

At a real return boundary, report actual effects or blocker, affected validation, protected comparison when material, next admitted action and any exact missing USER decision. Honor requested full digests and applicable decision/handoff detail. Routine progress need not repeat unchanged history. External PR/release waiting is pending until changed evidence; do not poll unchanged state into another gate. Safety budgets remain with the effect owner.

## Historical routes

Workstream, branch-record and closeout indexes locate historical records. Legacy `FB-###` paths, retired intake records, reform plans, old roots and dated inventories are historical/contextual unless a current owner explicitly admits their applicability. Preserve them without making old phase/path wording a current prerequisite. Repair conflicts only through the authorized carrier and owner.
